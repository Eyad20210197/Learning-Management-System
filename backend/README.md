# LMS backend

Production-oriented Phase 0 foundation for the single-owner LMS. The backend is a strict-TypeScript NestJS modular monolith with separate HTTP API and background-worker processes.

The current language and phase decision is recorded in [ADR-0001](../Documentation/Architecture/ADR-0001-typescript-phase-zero-foundation.md). It amends, but does not silently rewrite, the original [V1 implementation plan](../Documentation/LMS_V1_JavaScript_Implementation_Plan.md).

## Architecture

```text
LMS/
├── compose.yaml                     # Local PostgreSQL and Redis
├── backend/
│   ├── apps/
│   │   ├── api/                     # HTTP composition root
│   │   └── video-worker/            # BullMQ worker composition root; no HTTP server
│   ├── libs/
│   │   ├── identity/                # Users, auth, roles, sessions, devices
│   │   ├── learning/                # Courses, curriculum, enrollments, progress
│   │   ├── media/                   # Uploads, processing, playback
│   │   ├── operations/              # Audit and security operations
│   │   ├── platform/                # Config, Prisma, Redis, queues, observability
│   │   └── shared-kernel/           # Small, framework-neutral primitives
│   ├── prisma/                      # Prisma schema and migrations
│   └── prisma.config.ts
└── Documentation/
    └── Architecture/                # Architecture decision records
```

Business contexts follow this dependency direction:

```text
presentation -> application -> domain
infrastructure -> application/domain
apps -> context modules + platform adapters
```

The domain layer stays free of NestJS, Prisma, Redis, BullMQ, and HTTP details. Application code depends on narrow ports; infrastructure implements those ports; application entry points perform composition. Contexts must not import another context's infrastructure.

## Prerequisites

- Node.js `24.15.0` (the repository includes `.nvmrc` and `.node-version`)
- npm 11; `package.json` records the expected package-manager version
- Docker Engine or Docker Desktop with Docker Compose

Check the toolchain:

```bash
node --version
npm --version
docker compose version
```

FFmpeg, Cloudflare Wrangler, and R2 credentials are not required in Phase 0.

## Local setup

Run these commands from `backend/` unless noted otherwise.

```bash
npm ci
```

Create a local configuration file:

```powershell
# PowerShell
Copy-Item .env.example .env
```

```bash
# POSIX shell
cp .env.example .env
```

The example values bind PostgreSQL and Redis only to loopback and match the local Compose services. Never commit `.env`.

Start infrastructure, generate the Prisma Client, validate the schema, and apply checked-in migrations:

```bash
npm run infra:up
npm run prisma:generate
npm run prisma:validate
npm run db:migrate:deploy
```

Use `migrate dev` only when intentionally authoring a schema change:

```bash
npm run db:migrate:dev -- --name describe_the_change
```

Prisma migrations are never run automatically when the API or worker starts. The generated Prisma Client is ignored by Git and regenerated by build/type-check scripts.

Start the applications in separate terminals:

```bash
npm run start:api:dev
```

```bash
npm run start:worker:dev
```

Stop local infrastructure with `npm run infra:down`. Named Docker volumes preserve local data; removing those volumes is a separate destructive operation.

## Runtime endpoints

With the default `.env`:

| Endpoint                                      | Purpose                                                                                            |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `http://localhost:3000/api/v1/health`         | Dependency-aware PostgreSQL and Redis readiness check; returns `503` if either bounded check fails |
| `http://localhost:3000/api/docs`              | Swagger UI when `API_DOCS_ENABLED=true`                                                            |
| `http://localhost:3000/api/docs/openapi.json` | Generated development OpenAPI document when docs are enabled                                       |

The Swagger document is a development view of implemented endpoints. It does not replace the reviewed, source-controlled V1 contract that remains to be frozen.

## Configuration

Startup validation fails fast when required configuration is missing or invalid.

| Group           | Variables                                                                          |
| --------------- | ---------------------------------------------------------------------------------- |
| Application     | `NODE_ENV`, `API_PORT`, `APP_URL`, `CORS_ORIGINS`, `LOG_LEVEL`, `API_DOCS_ENABLED` |
| PostgreSQL      | `DATABASE_URL`, `DATABASE_POOL_MAX`                                                |
| Redis and queue | `REDIS_URL`, `VIDEO_QUEUE_PREFIX`                                                  |
| Local Compose   | `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`, `REDIS_PORT` |

`CORS_ORIGINS` accepts comma-separated HTTP(S) origins without paths. Disable API documentation in production unless it is deliberately protected and required.

## Production-shaped startup

Build once, apply migrations as a release step, and run API and worker as independent processes:

```bash
npm ci
npm run prisma:validate
npm run db:migrate:deploy
npm run build
npm run start:prod:api
```

Run `npm run start:prod:worker` in a second service/process with the same validated infrastructure configuration. Production deployment, TLS, Nginx, secrets management, backups, and monitoring are later release-readiness work.

## Phase 0 boundaries

This phase provides framework and infrastructure foundations only. It intentionally does not implement:

- authentication, RBAC, users, devices, sessions, or owner seeding;
- courses, lessons, enrollments, progress, or other LMS business schema;
- R2 storage, uploads, FFmpeg/FFprobe processing, or functional queue jobs;
- playback leases, HLS delivery, the Cloudflare media gateway, or the frontend;
- frozen ERD, state-machine, authorization-matrix, or canonical OpenAPI contracts;
- production deployment, backups, monitoring, or load/security suites.

The context modules and video queue are deliberate extension points, not claims that those product capabilities already exist.

## Troubleshooting

- Health returns `503`: run `npm run infra:logs` and confirm `DATABASE_URL` and `REDIS_URL` match the active Compose ports.
- Prisma imports are missing: run `npm run prisma:generate`.
- Port `3000`, `5432`, or `6379` is occupied: stop the conflicting local process or update the corresponding value in `.env` intentionally.
- Startup rejects configuration: use the complete error message and compare `.env` with `.env.example`; do not bypass validation.
